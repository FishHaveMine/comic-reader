# 漫画阅读器

一个针对 `twmanga.com`（包子漫畫）的桌面阅读器。不做网页套壳，而是**直接解析章节页、自建阅读界面**，因此没有任何广告与统计脚本，并把图片落盘缓存、自动预取下一话。

## 快速开始

```bash
npm install
npm start
```

启动后会自动打开上次阅读的章节（首次为示例章节）。地址栏可粘贴任意章节网址。

## Flutter Android 应用与进度同步

已增加 `mobile/` Flutter Android 工程，实现与桌面对应的阅读流程。两端保存章节、当前页与页内位置，重启可恢复，并在 ADB 连接时双向同步。

```bash
npm run android:build   # 构建 release APK，需要 Flutter / Android SDK / JDK
npm run android:install # 安装到一台已授权的 ADB 手机并启动
npm start               # 桌面启动后自动建立 ADB 通道并配对
```

同步改为手动：点击桌面底部同步按钮或手机底部同步按钮才交换两端数据。启动、ADB 配对、切回前台和收藏操作仅在本机保存，不触发同步。旧客户端的自动同步请求会被拒绝。同步时逐本比对桌面与手机的最后阅读时间，双方都保留时间较新的记录（包括回看时较小的页码）。时间相同则使用一致的冲突规则；延迟保存沿用实际阅读时间，切后台、退出及重复同步不会刷新旧位置的时间。一次手动同步期间继续阅读会在该次操作内补发最新记录；点击继续阅读时重新读取最终合并结果。断线本地保存，重连后点击同步。后台导入新进度时显示继续阅读入口，不自动打断当前阅读。图片缓存与验证 cookie 由两端独立维护。

详见 [Android 构建、同步与测试说明](mobile/README.md)。

## 返回首页与搜索

桌面工具栏和手机顶部的房屋图标可打开指定分类页：
`https://www.baozimh.com/classify?type=all&region=all&state=all&filter=%2a`。

直接使用站点搜索框搜索漫画，打开漫画目录并选择章节后，会自动回到自建阅读器，继续使用缓存、收藏和阅读进度。兼容站点按地区跳转到 `cn.bzmgcn.com`。手机首页提供后退、分类首页、刷新和返回阅读；桌面首页窗口可按 Esc 关闭返回阅读，Alt+← 后退，Ctrl/Cmd+R 刷新。

首页与目录是站点浏览界面，阅读章节仍使用原生界面。首次访问首页可能需要站点的浏览器验证，验证 cookie 与阅读会话共用。

## 收藏与手机沉浸阅读

桌面工具栏星标和手机顶部星标用于收藏/取消收藏当前漫画，旁边的收藏列表可继续最近阅读的章节与页内位置。按漫画去重，翻章不会生成重复收藏；桌面收藏列表可搜索漫画或章节。收藏与取消收藏沿用 ADB 双向同步，离线取消的收藏不会在重连后被旧记录恢复。

手机操作栏在滚动时或 3 秒无操作后自动收起，轻触正文唤出。工具栏覆盖在正文上，收起时漫画尺寸与阅读位置保持不变；隐藏时只保留轻量页码。点击链接图标输入网址，点击漫画标题回到顶部；输入网址、打开收藏、章节加载或出错时保持操作栏可用。

## 为什么不是简单地套一个 webview

这不是偷懒与否的问题，实测下来套壳根本不可用：

| | 原站页面 | 本阅读器 |
| --- | --- | --- |
| 页面负载 | AMP 页 + Outbrain 广告、91app 统计、impactify cookie-sync 链 | 1 个 HTML 请求（约 117KB） |
| 失败请求 | 21 条（广告/统计域名 SSL 握手失败） | 0 |
| `load` 事件 | **始终不触发**（被广告 iframe 拖住，实测 60s 内未完成） | 不适用 |
| 图片请求 | 由站点 JS 控制，无法干预 | 可控：并发 6、失败重试、磁盘缓存 |

站点在 `__gatekeeper_challenge` 浏览器验证网关后面，普通 HTTP 请求一律 403。本项目的做法是：**首次用隐藏窗口把验证跑过去，之后复用同一会话直接抓 HTML 与图片**。

## 漫画章节选择

桌面工具栏点击「章节目录」，手机点击底部「页码 · 目录」打开当前漫画全部章节。支持 twmanga、baozimh、bzmgcn、dzmanga 网址，以及 `0_89_3.html` 等分段章节；目录主章节标记对应的当前分段阅读位置。支持搜索章节名、正序/倒序排列、标记当前阅读章节，点击章节后进入阅读器并按已有进度恢复。首次加载目录需要联网，之后优先使用持久化目录；点击刷新可获取更新章节，刷新失败仍可选择已缓存的章节。

## 图片加载速度是怎么优化的

1. **自建渲染、砍掉全部第三方脚本**——只请求章节 HTML 和正片图片，广告与统计域名直接拉黑。
2. **磁盘缓存**（`userData/image-cache`）：按图片 URL 的 SHA-1 命名，命中即零网络请求。重复阅读同一话是瞬时的。连续阅读期间保留本次阅读章节。
3. **中段接续**：阅读至章节中段后追加下一章并缓存图片，后台请求与前台加载复用任务。手机还向后缓存两章。
4. **缓存恢复**：章节信息与图片均持久化，重启优先使用磁盘内容。
4. **按需加载**：只加载视口附近（前 1600px）的图片，首屏前 2 页立即加载、首图 `fetchpriority=high`。
5. **并发受限 + 失败重试**：全局最多 6 个并发下载，单请求 15 秒超时（超时保护是必需的，见下），失败重试 3 次并退避。
6. **正在看的图优先**：后台预取会把队列排满，所以从自定义协议来的请求（即渲染进程正在显示的图）会**插到队首**，滚动时不会被几十张预取图堵住。
6. **预留版面**：用页面里给出的 `width`/`height` 设置 `aspect-ratio`，图片到达时不会把下方内容顶开，滚动不跳。

## 图片顺序（曾经踩过的坑）

站点的 `id` 是 **两段结构**，不是单调递增的页码：

```
<amp-img id="chapter-img-1-3" src=".../10.jpg">     真实页码 = 段 * 6 + 段内序号 + 1
```

`alt` 末尾的数字同样是**段内序号**，不是全局页码。按 id 第二段排序会把第 1、7、13… 页排到最前面 —— 这是实现过程中真实出现过并修掉的 bug。

现在的排序依据是 **CDN 文件名里的页码**（`1.jpg`、`2.jpg`…，互不重复的纯数字序列），并在文件名不是数字或数字重复时退回 DOM 顺序（站点本身按阅读顺序输出）。

验证方式：4 话 163 页逐页核对，「DOM 顺序 / 文件名页码 / id 两段还原出的页码」三个信号完全一致；另有单测锁死这个回归。

## 加载提示的时机

覆盖层只在**真正需要等**的时候出现，而且文案分级：

| 情况 | 表现 |
| --- | --- |
| 首次打开（要过站点验证） | 覆盖层提示「首次访问需要先通过站点验证」 |
| 翻到已预取的下一话 | **完全不弹** —— 解析结果在内存、图片在磁盘，零网络请求 |
| 网络慢但不需要验证 | 覆盖层提示「正在加载章节…」，不会谎称要过验证 |

做对这件事的关键有两处：预取过的章节会连同**解析结果**一起留在内存（翻章时直接命中，不再请求页面），覆盖层则延迟 400ms 才出现（秒开时根本来不及闪）。

## 缓存保留策略

磁盘缓存维持在**当前章 + 后面两章**：每翻一话，预取链结束后会清理掉窗口之外的图片。不这么做缓存会无限增长 —— 实测几轮阅读后积累到 419 张 / 110MB，清理一次降到 70 张 / 19MB。

两道安全阀，防止「清理」变成「清空」：

- **保留集为空时一张都不删**：上游拿不到当前章的图片清单时（理论上不该发生），直接跳过。
- **预取链有任何一章抓失败（含图片部分失败）就放弃本次清理**：此时保留清单不完整，删掉的可能正是下次要读的内容。

代价是往回翻上几话需要重新下载（一次约 6~7 秒）。状态栏会显示当前缓存占用与保留策略。

## 代理策略（重要）

**默认直连，忽略系统代理。** 这是实测结论，不是猜测。本机系统代理为 `127.0.0.1:7890`，每组 6 张 CDN 图片：

| 连接方式 | 结果 |
| --- | --- |
| 走系统代理 | 成功 **2/6**，其余全部挂起到超时，总耗时 18s+ |
| **直连** | 成功 **6/6**，总耗时 **2.2s** |
| 走代理并尝试绕过 CDN 域名 | 绕过规则未生效，成功 3/6，单张最慢 42.7s |

代理会挂死 CDN 的绝大多数请求（不是慢，是永远不返回），所以阅读器默认绕过。

换到必须走代理的网络时，用环境变量恢复：

```bash
COMIC_USE_SYSTEM_PROXY=1 npm start
```

其他调试开关：

```bash
COMIC_DEBUG=1 npm start        # 打印每张图片的下载耗时
COMIC_TIMEOUT=8000 npm start   # 调整单请求超时（毫秒）
```

## 快捷键

| 快捷键 | 作用 |
| --- | --- |
| `←` / `→` | 上一话 / 下一话 |

后两章已在后台缓存，所以切换基本是瞬时的。地址栏聚焦时方向键仍然用于移动光标，不会误翻章；状态栏底部常驻显示这条提示，不用去猜。

## 连续阅读与缓存恢复

默认开启连续阅读。当视口到达当前章一半时，自动加载并追加下一章，同时预缓存图片；没有倒计时或跳顶。进入新章节后，标题、页码和双向同步进度按当前实际章节更新。工具栏可关闭后续追加；网络失败后继续滚动会重试。

两端将章节信息和图片保存至磁盘，再次启动时优先读取本地缓存。手机先恢复本地阅读，ADB 同步在后台进行，不阻塞正文。连续阅读期间保留已追加章节，避免往回滚时缓存被清理。未缓存的章节或图片仍需网络加载。

## 阅读流程稳定性

- 快速提交多个地址时，只展示并记住最后一次请求；前台打开和后台预取共用正在进行的章节解析，避免重复访问。
- 切换章节后，旧预取链停止继续推进，不再更新当前章节进度或清理新章节的缓存。预取完成后释放任务，重访已清理章节会重新检查磁盘并补齐图片。
- 正在看的图片若已在预取队列中等待，也会提升到队首，无需重新下载。
- 单页图片支持连续重试，成功页数只计一次；切换章节后，旧图片回调不会污染新章节计数。
- 打开失败可重试，也可返回当前章节；加载期间同样可以返回，晚到的结果不会重新覆盖阅读内容。
- 章节末尾没有下一话时停止追加；遇到循环导航也不会重复追加。
- 窄窗口优先保留地址输入与翻章操作，自动翻章开关提供可访问的选中状态。

界面回归使用真实 Electron、实际 preload 与 DOM，站点响应和图片失败由测试模拟，不访问线上站点，也不读取或修改用户阅读配置。

## 多平台构建与产物归拢

`scripts/build.js` 负责「选平台 → 构建 → 把产物收拢到一个文件夹」：

```bash
npm run build                  # 交互式选择（1. 桌面端 / 2. Android / 3. 全部）
npm run build:desktop          # 只构建桌面端
npm run build:android          # 只构建 Android
npm run build:android -- --aab # 顺带构建 release AAB
node scripts/build.js -p all -o release   # 指定平台与输出目录
```

产物统一落在 `dist/`（可用 `-o/--out` 改名），各平台各占一个子目录，互不覆盖：

```
dist/
├── desktop/漫画阅读器.app     生成图标并组装 .app 启动壳（与 npm run shortcut 同一套逻辑）
├── android/app-release.apk    flutter build apk --release 的产物（附带 .sha1）
└── build-manifest.txt         本次构建的平台、版本、时间与目录清单
```

- 桌面端刻意不引入 electron-builder：`dist/desktop/漫画阅读器.app` 同样是**启动壳**，内部记录项目绝对路径，始终运行最新源码；因此它只适合本机/同路径使用，移动项目目录后需重新构建。
- 桌面端依赖 macOS 的 `sips` / `iconutil`；其他系统只会显示 Android 选项。
- 单独构建某一平台时，只清空并重写该平台子目录，已构建的其他平台产物会保留。

## 桌面快捷方式（macOS）

```bash
npm run shortcut
```

会在桌面生成 `漫画阅读器.app`，双击即可启动。

它只是一个**启动壳**，内部记录项目路径并直接执行项目里的 Electron，因此始终运行最新的代码 —— 改完源码不需要重新生成快捷方式。

- 图标由 `scripts/make-icon.js` 生成：纯 Node 手写 PNG 编码（IHDR/IDAT/IEND）+ 3 倍超采样抗锯齿，不引入任何图像库。
- 双击启动看不到 stderr，运行日志写在 `~/Library/Logs/Comic Reader.log`。
- 移动项目目录后需要重新执行 `npm run shortcut`；桌面图标没刷新时执行 `killall Finder`。
- 仅针对 macOS。

## 已知限制

- **解析依赖站点版式**。正片图片靠 `id="chapter-img-<段>-<段内序号>"` 约定识别（顺序见上一节），导航靠 `id="next-chapter"` / `id="prev-chapter"`。站点改版会导致解析失败，代码里有「退化为收 CDN 图片」的兜底，但章节名可能取不准。
- **只支持这一类章节页**。其他漫画站的 DOM 结构不同，需要各自写适配。
- **验证网关是按出口 IP 放行的**。切换网络或代理后可能触发重新验证，阅读器会自动补一次（开隐藏窗口重跑挑战，约 10~25 秒），期间界面会给出提示。
- 广告拦截用的是域名黑名单，只覆盖实测遇到的广告与统计域名。
- 连续阅读保留本次已追加的章节，长时间阅读会增加缓存占用；没有缓存的内容需联网。
- 缓存清理依据的是「当前章的图片清单」，因此同一章被站点改动（少页/换图）后，旧图会残留到下次清理。
- 阅读进度记忆使用当前页与页内比例，跨设备保持相同阅读位置；站点章节内容变化后会将页码限制到当前章范围。
